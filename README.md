# Clean WordPress Export для Local

Доповнення для Local 10.2.0 або новішої версії. Створює ZIP з файлами WordPress і свіжим SQL-дампом бази. Файли WordPress розміщуються в корені архіву:

```text
index.php
wp-config.php
.htaccess
wp-admin/
wp-includes/
wp-content/
database.sql
```

Архів містить вміст `app/public` після застосування виключень. Сусідні папки `conf`, `logs`, `app/sql`, метадані Local та старі SQL-дампи з `app/sql` не додаються. Приховані файли WordPress зберігаються. Якщо в корені WordPress уже є `database.sql`, новий дамп отримає вільне ім'я `database-1.sql`, `database-2.sql` тощо; наявні файли не перезаписуються.

## Встановлення

1. Відкрийте **Local → Add-ons → Install from disk**.
2. Виберіть `dist/local-clean-export-1.1.1.tgz`.
3. Увімкніть **Clean WordPress Export** і перезапустіть Local.

Пакет уже містить готовий JavaScript. Встановлювати Node.js або завантажувати npm-залежності для роботи доповнення не потрібно. Воно використовує бібліотеки, що постачаються з Local.

Код для репозиторію міститься в `~/Work/local-clean-export`, а встановлена копія на Linux — у `~/.config/Local/addons/local-clean-export`. Для ручного оновлення повністю завершіть Local і замініть вміст встановленої папки файлами з папки `package/` усередині нового `.tgz`, після чого знову відкрийте Local. Повторне **Install from disk** для вже встановленого доповнення може показувати **addon already exists**.

## Використання

1. Запустіть потрібний сайт у Local.
2. Відкрийте **Tools → Clean WordPress Export**.
3. За потреби заповніть поле **Новий домен** або залиште його порожнім для звичайного експорту.
4. Натисніть **Експортувати WordPress** і виберіть місце для ZIP поза папкою сайту Local.
5. Дочекайтеся повідомлення про завершення. Кнопка **Показати архів** відкриває його розташування.

Експорт можна скасувати. При помилці або скасуванні тимчасові файли видаляються, а попередній ZIP у вибраному місці зберігається. Доповнення не змінює WordPress, базу або штатний експорт Local. Дамп записується в окрему тимчасову папку з обмеженим доступом.

## Заміна домену

Необов’язкове поле **Новий домен** змінює домен тільки в SQL, що потрапляє до ZIP:

- Порожнє поле або самі пробіли — експорт SQL без замін.
- `example.com` — замінити поточний домен Local на `example.com`, зберігши наявні `http://` та `https://`.
- `https://example.com` — додатково перевести URL зі старим доменом на HTTPS.
- Допускаються порт та міжнародні домени; міжнародні назви нормалізуються до ASCII/Punycode. Шлях, параметри, фрагмент і облікові дані в адресі не допускаються.

Поточний домен береться з налаштувань обраного сайту Local і показується біля поля. Після експорту панель показує старий домен, новий домен та кількість замін. Якщо збігів немає, це також відображається. Поле не зберігається між перезапусками програми.

Порядок роботи: `mysqldump` створює тимчасовий дамп → доповнення змінює значення в його `INSERT`/`REPLACE`-рядках → ZIP отримує готовий SQL. Заміна працює з файлом і **не підключається до робочої бази, не виконує UPDATE і не завантажує WordPress або його плагіни**.

Підтримуються звичайні рядки, JSON із екранованими слешами, PHP-серіалізовані масиви, об’єкти, посилання та вкладена серіалізація. Довжини рядків перераховуються у байтах; об’єкти не створюються і PHP-код не виконується. Серіалізовані дані в шістнадцяткових BLOB-значеннях також обробляються. Бінарні дані дампуються через `--hex-blob`. Коментарі, схеми таблиць і збережені процедури залишаються як у вихідному дампі.

Заміна охоплює входження поточного домену в значеннях усіх експортованих таблиць, зокрема `home`, `siteurl`, контент, метадані та GUID. Для нестандартного `Serializable`-об’єкта підтримується лише вміст у форматі стандартної PHP-серіалізації. Пошкоджена серіалізація або невідомий формат із доменом зупиняє експорт з помилкою, щоб не створити пошкоджену базу. Для таких даних залишається доступним звичайний експорт із порожнім полем.

Ця функція змінює лише SQL. Наявний `wp-config.php`, файли тем і плагінів у ZIP залишаються без змін. Під час розгортання потрібно налаштувати облікові дані бази; якщо домен жорстко заданий у `WP_HOME` / `WP_SITEURL` у `wp-config.php`, ці константи слід оновити окремо.

## Виключення

Використовуються збережені налаштування **Preferences → Exporting → File exclusion filter**. Натисніть **Apply** після зміни налаштувань Local. Доповнення читає фільтр заново перед кожним експортом, після вибору місця збереження. Кнопка **Оновити виключення** оновлює показаний у панелі фільтр.

Приклади значень через кому:

```text
*.zip, *.tar.gz, *.bz2, *.tgz, node_modules, .git, wp-content/cache/, *.log
```

- `*.zip`, `*.log` — виключити файли за розширенням у всіх папках.
- `node_modules`, `.git` — виключити папки з такими назвами на будь-якій глибині.
- `wp-content/cache/` — виключити папку від кореня WordPress та весь її вміст.
- `/app/public/wp-content/cache/**` — також підтримується шлях у форматі штатного експорту Local.

Використовується та сама бібліотека `micromatch`, що й у Local, з підтримкою прихованих файлів (`dot: true`). Додатково зіставляються шляхи від кореня WordPress, а виключені папки не обходяться. Як і в Local, `local-site.json` та `pressmatic-site.json` виключаються за замовчуванням. Якщо налаштування ще не збережені, використовується штатний фільтр Local: `*.zip, *.tar.gz, *.bz2, *.tgz`. Якщо фільтр пошкоджено, експорт завершується помилкою.

**Свіжий SQL-дамп додається завжди**, навіть якщо фільтр містить `*.sql`. Це гарантує, що результат містить і файли, і базу даних. Фільтр застосовується до наявних файлів WordPress, а не до нового дампу.

## Особливості

- Сайт має працювати: використовується актуальний дамп з `mysqldump`, який постачається з обраною MySQL/MariaDB-службою Local.
- Для таблиць InnoDB використовується `--single-transaction`. Зміни файлів і таблиць інших типів під час експорту не утворюють спільного миттєвого знімка. Для узгодженого архіву утримайтеся від редагування сайту, оновлень плагінів і змін схеми бази до завершення.
- Символічні посилання всередині WordPress зберігаються як відносні. Зовнішні й пошкоджені посилання пропускаються; їх кількість показується після експорту. Доповнення не обходить пов'язані зовнішні папки.
- У ZIP зберігається наявний `wp-config.php`; заміна домену в базі виконується лише при заповненому полі **Новий домен**.
- Це звичайний ZIP WordPress + SQL, без службового маніфесту Local. Він не додається до історії вбудованих Local Backups.
- Перевірено на Linux з Local **10.2.0+7022**: інтеграційні тести й експорт запущеного сайту `ademcorp` (26 256 файлів WordPress та SQL-дамп 3 171 906 байтів). macOS і Windows потребують окремої перевірки в Local.

## Розробка та перевірка

```bash
npm run check
npm test
npm run pack
```

Тести запускаються через Electron установленого Local та використовують його справжні `archiver`, `micromatch`, React і ZIP-reader. Для незалежної перевірки серіалізації потрібен PHP 8.1+ у `PATH`; інший виконуваний файл можна задати через `TEST_PHP`. За потреби задайте `LOCAL_EXECUTABLE` (шлях до виконуваного файлу Local) та `LOCAL_APP_PATH` (шлях до `resources/app.asar`). Тести створюють окремі тимчасові сайти, не торкаючись ваших сайтів і налаштувань. Набір тестів розрахований на Linux/macOS (для імітації `mysqldump` використовується `/bin/sh`). Для роботи самого доповнення окремий PHP не потрібен.

Перевірки охоплюють склад реального ZIP, фільтри, рекурсивні виключення папок, приховані файли, Unicode, свіжий SQL при `*.sql`, колізії назв, символічні посилання, помилки та скасування `mysqldump`, збереження попереднього архіву при помилці, очищення тимчасових файлів, реєстрацію main/renderer і рендеринг панелі. Заміна домену перевіряється для порожнього поля, HTTP/HTTPS, JSON, багатобайтних та бінарних рядків, BLOB, вкладеної PHP-серіалізації, об’єктів і посилань, великих SQL-рядків, відсутності збігів, помилок та скасування. Тестові очікувані результати генеруються справжнім PHP через `serialize()` і перевіряються через `unserialize()`.

Документація Local: [Building your Add-on](https://localwp.com/help-docs/building-your-add-on/), [Context API](https://localwp.com/help-docs/building-your-add-on/context-api/). Точки інтеграції та формат налаштувань перевірено за встановленою версією Local. Формат серіалізації й обробку байтів описано в [PHP serialize](https://www.php.net/manual/en/function.serialize.php), SQL-екранування — у [MySQL String Literals](https://dev.mysql.com/doc/refman/8.4/en/string-literals.html), формат бінарних значень — у [mysqldump --hex-blob](https://dev.mysql.com/doc/refman/8.4/en/mysqldump.html#option_mysqldump_hex-blob).
